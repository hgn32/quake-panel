# VSCode を閉じても Claude Code に開発を続けさせる方法

VSCode 拡張機能のチャットは、VSCode を閉じると実行が止まる（履歴は残るが、閉じている間は進まない）。
コードのあるサーバは常時稼働なので、**サーバ側（devcontainer 内）で CLI を tmux 上で動かす**ことで、
VSCode やノート PC を閉じても作業を継続させられる。

## 仕組み

- `~/.claude`（ホストの `$HOME/.claude` をマウント）に**認証情報とチャット履歴**が入っており、
  拡張機能と CLI で共有される。ログインは不要で、拡張機能で進めたチャットの続きを CLI から再開できる。
- tmux はターミナルの中に「切断しても生き続ける仮想画面」を作るツール。
  この中で `claude` を動かせば、SSH や VSCode を閉じてもプロセスはサーバで動き続ける。
- tmux / claude CLI / プロキシ用ラッパー（`/usr/local/bin/claude`）は Dockerfile でイメージに組み込み済み。

## 使い方

```bash
# 1. VSCode のターミナル（または SSH）で tmux セッションを作る
tmux new -s work1

# 2. その中で Claude を起動
cd /workspaces
 laude --resume        # ← 一覧から過去セッションを選びたい場合
# claude --continue        # 直近のチャットの続きから再開
# claude                 # ← まっさらな新規セッションで始める場合

# 3. 作業指示を出したらデタッチ（Ctrl+B を押してから D）
#    → VSCode / SSH / ノート PC を閉じてもタスクは続行される

# 4. 様子を見るときは再アタッチ
tmux attach -t work1
```

### VSCode のターミナルから使う場合の注意

素の VSCode は `Ctrl+B` を「サイドバーの表示切替」に割り当てており、統合ターミナル内でも
シェルに渡さないため、tmux のプレフィックスキーが効かない。本プロジェクトでは
`devcontainer.json` の `terminal.integrated.commandsToSkipShell` で
`Ctrl+B` をターミナルに渡すよう設定済み（ターミナル外では従来どおりサイドバー切替）。
設定変更後は VSCode のウィンドウ再読み込みが必要。SSH など VSCode 外のターミナルでは元々問題ない。

補足: `fg: current: no such job` というエラーは「一時停止中のジョブがない」という意味。
`Ctrl+Z` でプロセスを止めたあとに `fg` で戻る操作なので、何も止めていなければ出るのが正常。
tmux 内では `fg` を使う場面はほぼなく、ウィンドウ切り替え（`Ctrl+B` → 番号）で行き来すればよい。

## 複数のタスクを並行で走らせる

### 方法1: tmux のウィンドウを増やす（見ながら操作したい場合）

tmux は1つのセッション内に複数の「ウィンドウ」（タブのようなもの）を持てる。

```bash
tmux attach -t work
# Ctrl+B → C で新しいウィンドウを作成 → そこで2つ目の claude を起動
cd /workspaces && claude
```

| キー | 操作 |
| --- | --- |
| `Ctrl+B` → `C` | 新しいウィンドウを作る |
| `Ctrl+B` → `0`〜`9` | 番号でウィンドウ切り替え |
| `Ctrl+B` → `W` | ウィンドウ一覧から選ぶ |
| `Ctrl+B` → `D` | デタッチ（全ウィンドウ動いたまま抜ける） |

それぞれのウィンドウの `claude` は完全に別セッション（別チャット）になる。

### 方法2: バックグラウンド実行（放置したい場合）

対話画面を開かずにタスクだけ投げる方式。

```bash
claude --bg "server のテストを全部実行して失敗を修正して"
claude --bg "README を最新の構成に合わせて更新して"
claude agents   # ダッシュボードで全タスクの進捗を監視・アタッチ
```

### 並行時の注意: 同じ作業ツリーの取り合い

複数セッションが**同じ `/workspaces` のファイルを同時に編集すると衝突する**
（片方の変更をもう片方が上書きする等）。並行させるタスクは次のいずれかにすること。

- 触るファイルが重ならないタスク同士にする（例: server 側と client 側、コード修正とドキュメント）
- git worktree で作業ツリーを分ける。ブランチごとに独立したディレクトリができるので安全:

  ```bash
  git worktree add /workspaces-feature-x feature-x
  cd /workspaces-feature-x && claude
  ```

また、プランのレート制限は全セッション共有のため、同時に走らせすぎると全体が遅くなる。
まずは 2〜3 並行から試すのがよい。

### 外出先から確認・指示したい場合

tmux 内で `claude --remote-control` として起動しておくと、そのセッションを
claude.ai/code のブラウザやスマホの Claude アプリから操作できる。

## 注意事項

- **同じセッションを拡張機能と CLI で同時に開かない**こと。
  CLI に移ったら、VSCode 側の該当チャットには続きを書かない。
- 引き継がれるのは会話履歴・モデル・権限モード。実行中タスクの「途中状態」までは復元されない。
- 全画面の tmux 操作に慣れないうちは、`tmux kill-session -t work` でいつでも作り直せる。

## コンテナ再ビルド時の挙動

| もの | 場所 | 再ビルド後 |
| --- | --- | --- |
| チャット履歴・認証情報 | `~/.claude`（ホストマウント） | **残る** |
| tmux / claude CLI 本体 | イメージ内（Dockerfile で導入） | **残る** |
| 初回ウィザード完了フラグ | `~/.claude.json`（マウント外） | 消えるが `postCreateCommand.sh` が自動で再設定する |
| ワークスペース信頼設定 | `~/.claude.json`（マウント外） | 消える。**初回起動時に信頼ダイアログを1回承認し直す** |

`~/.claude.json` に初回ウィザード完了フラグ（`hasCompletedOnboarding`）が無いと、
有効な認証情報があっても CLI がブラウザでの再ログインを要求してくる。
このフラグは `postCreateCommand.sh` がコンテナ作成時に自動で立てるため、通常は意識しなくてよい。
