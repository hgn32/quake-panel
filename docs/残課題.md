## A. 実機投入までに必須

実機 (N150 サーバー / Raspberry Pi 4) が要るため、リポジトリ側では実施できていない。

### A-1. Docker イメージのビルドと起動確認

`Dockerfile` と `docker-compose.yml` は書いてあるが、**ビルドを一度も通していない**
(開発環境に Docker が無かった)。N150 上で最初に確認すること。

```bash
docker compose up -d --build
docker compose logs -f          # kmoni/P2P への接続が立つか
curl -s localhost:8080/healthz  # 200 が返るか
```

見るべき点:

- [ ] マルチステージビルドが通る (`npm ci` → `npm run build` → `npm prune`)
- [ ] `STATIC_DIR=/app/public` にクライアントの成果物が入っている (画面が出る)
- [ ] `TZ=Asia/Tokyo` でも UTC でも表示時刻が JST になる (時刻処理は TZ 非依存に書いてある)
- [ ] HEALTHCHECK が healthy になる
- [ ] `docker compose restart` で素直に落ちて上がる (SIGTERM ハンドラを入れてある)

### A-2. リバースプロキシの設定と疎通

`deploy/nginx/quake-panel.conf` は設定例で、**実際に適用した確認はしていない**。

- [ ] `htpasswd -c /etc/nginx/quake-panel.htpasswd <ユーザー名>` で認証ファイルを作る
- [ ] 証明書 (Let's Encrypt なり自己署名なり) と DNS/hosts を用意する
- [ ] **wss の疎通** — ここが一番こけやすい。`Upgrade`/`Connection` を明示していないと
      WebSocket が張れない。ブラウザの DevTools で `/ws` が 101 になることを見る
- [ ] `proxy_read_timeout` の延長が効いているか。劣化モード中 (フレーム通知が止まる)
      でも 60 秒で切られないこと
- [ ] 会社 PC からのアクセス経路を決める (固定 IP なら `allow`、そうでなければ Basic 認証のみ)
- [ ] `/healthz` だけ認証を外してある。外形監視から叩くかどうかを決める

> **利用条件上の必須事項**: 入場制限は §2(1) の成立条件。認証を外した状態で
> インターネットに公開しないこと。

### A-3. Pi4 キオスクの設定

`deploy/kiosk/` に起動スクリプトと手順を置いてある。

- [ ] `quake-panel-kiosk.sh` を autostart に登録する
- [ ] 初回に手動でログインして、Basic 認証の資格情報を Chromium プロファイルに保存させる
- [ ] 電源断からの自動復帰 (再起動 → 自動でパネルが出る) を確認
- [ ] `--autoplay-policy=no-user-gesture-required` で音が鳴ることを確認。
      鳴らない場合は画面をタップして音声を有効化する導線が出るようにしてある

### A-4. 受け入れ条件のうち実測が要るもの (検討書 §6)

- [ ] **72 時間ソークテストでメモリ増加なし (サーバー・Pi4 双方)**
      - サーバー: 開発環境での 60 秒観測では RSS 84〜86MB で横ばいだった。
        画像はリングバッファ (既定 30 フレーム × 3 レイヤ) に置くだけなので
        上限は決まっているが、72 時間は未確認。
      - Pi4: `ImageBitmap` は差し替え時に必ず `close()` する作りにしてあるが、
        Chromium 側の挙動込みでの確認が必要。
      - 記録方法の例:
        ```bash
        # サーバー側
        while :; do date -Is; docker stats --no-stream --format '{{.MemUsage}}' quake-panel; sleep 300; done | tee soak-server.log
        # Pi4 側
        while :; do date -Is; ps -o rss=,pid=,comm= -C chromium-browser; sleep 300; done | tee soak-kiosk.log
        ```
- [ ] **Pi4 フル HD で平常時 CPU 使用率の実測 (目安を仕様化)**
      - 測ったうえで README に「平常時 CPU 使用率 N% 以下」と書く。
      - 重かった場合の逃げ道は用意してある:
        設定の「観測点を発光表示」を切る / `KMONI_IDLE_FRAME_INTERVAL_SEC=2` にする。
      - どちらでも足りない場合は、地図の描画スケール上限を入れる改修が要る。

## B. 実データ待ちの確認

平常時には流れてこない電文があり、モックでしか確認できていなかった部分。
発生を待ち構える必要はない:

- **kmoni は過去タイムスタンプで遡れる** (`.../hypo/eew/{YYYYMMDDhhmmss}.json` や
  各画像は過去の発生時刻を指定すれば取得できる。少なくとも数週間分)。
  発生時刻は P2P の履歴 API (551) で分かる
- **P2P は公式仕様書 (OpenAPI) と気象庁情報 API (`/v2/jma/*`) がある**
- **実動作 (音・明滅・パネル) は `scripts/replay-upstream.mjs`** で実物と同形の
  電文を再生して確認する (下記 B-1〜B-3 参照)

### B-5. EEW の警報対象地域の県名表記

**仕様と実電文で確定済み** (2026-08-17)。P2P の公式仕様書 (OpenAPI) で
`areas[].pref` は**府県予報区** (気象庁 AreaForecastLocalEEW コード表・全 56 区)
と明記されており、コード表の全 56 区を取得して照合方法を決めた:

- 43 区は「熊本」「宮崎」のような接尾辞なしの県名 → 「都道府県」の末尾を吸収する
  正規化付き完全一致 (`shared/src/eewRelevance.ts`) で照合。実電文 (2026-07-29、
  pref=「熊本」「鹿児島」) でも確認
- 県名でない 13 区 (北海道道央/道南/道北/道東・伊豆諸島・小笠原・奄美(群島)・

- 震源不明の警報は緯度経度が `-200` で来る (仕様書に明記) ため、範囲外座標を
  「震央不明 = 鳴らす側に倒す」へ正規化する (`server/src/sources/p2pParse.ts`)

## C. 既知の割り切り (仕様として受け入れているもの)

直すべき欠陥ではなく、判断の結果こうしてある。将来ひっくり返すときの材料として残す。

### C-1. 延岡のリアルタイム震度は数値で出せない

強震モニタ画像の色から震度値を復元する処理は、利用条件で名指しで
「意図しない利用」とされているため行わない (§2(2)、検討書 Phase 4 除外)。
延岡付近の震度は、地震後に気象庁が発表した実測値 (P2P 551) を履歴パネルに出す。

つまり **揺れている最中に延岡の数値は出ない**。地図上の色で見る形になる。

### C-2. 到達予測は自前計算しない

独自に地震動を予測して表示することは気象業務法の制限を受ける (§2(3))。
到達予測時刻は気象庁が配信した値 (P2P 556 の `areas[].arrivalTime`) を
そのまま表示するだけで、**警報対象地域に入っていない場所の到達時刻は出せない**。
EEW パネルの「発震から N 秒」は経過時間であって予測ではない。

### C-3. 津波予報区の強調は都道府県ポリゴンの流用

背景地図が都道府県ポリゴンなので、予報区名から都道府県を名前で引いて塗っている。
「有明・八代海」「瀬戸内海沿岸」のような予報区は対応する図形が無く、
**地図上では塗られない** (パネルには文字で出る)。

厳密にやるなら気象庁の津波予報区 GIS データ
(https://www.data.jma.go.jp/developer/gis.html) を取り込んで、
`scripts/build-basemap.mjs` と同じ要領で kmoni 座標系へ投影した
予報区ポリゴンを別アセットとして持つ必要がある。手間の割に効果が
限定的なので初回では見送った。

### C-4. 座標系は較正値であって公式値ではない

kmoni は投影パラメータを公開していない。基図と観測点配置から求めた値
(残差 RMS 0.7px 未満) を `shared/src/kmoniGeo.ts` に持っている。

**kmoni 側で基図が差し替えられると背景地図がずれる。** そのときは再較正する:

```bash
python3 scripts/calibrate-kmoni-map.py --overlay /tmp/overlay.png
```

南西諸島のインセットは「同縮尺の平行移動」で近似している。実測では
scale=0.997 だったので 1.0 として扱っており、この島々の位置には
1px 程度の誤差が乗りうる。

### C-5. 通知音は合成音

音源ファイルを同梱せず WebAudio で合成している (素材の配布条件を持ち込まないため)。
気象庁のチャイム音を模した音は、紛らわしいうえ配布条件も別途あるので使っていない。

気に入らなければ `client/src/core/audio.ts` の `PATTERNS` を書き換える。
音源ファイルを使いたい場合は、その素材のライセンスを確認してから
`client/public/` に置いて `<audio>` 方式に変える。

### C-6. EEW の表示終了は保持期間による打ち切り

P2P 556 には最終報フラグが無い。kmoni の `is_final` は取れるが、
最終報のあとも少し表示を残したいので、**続報が 180 秒途切れたら消す**
(`EEW_RETENTION_MS`) という単純な作りにしてある。

最終報を受けたらもっと早く畳みたい、という要望が出たら
`server/src/eew/coordinator.ts` の `sweep()` に `isFinal` の分岐を足す。

### C-7. UI シェルは素の TypeScript

検討書 §5 の判断どおり、描画コア (`client/src/core/`) はフレームワーク非依存にし、
UI シェル (`client/src/ui/`) は素の TS で書いた。参考 A 並みの作り込み
(タブ切替・詳細パネル) に進むなら Preact 導入を検討する余地があるが、
描画コアには手を入れずに済む構造にしてある。

## D. 将来の改善案 (優先度低)

思いついたものを置いておく。どれも今すぐ要るものではない。

- [ ] **地図のズーム / パン操作** — いまは「日本全体」「利用地周辺」の 2 択のみ。
      キオスクはタッチ操作しない前提なので優先度は低い。
- [ ] **地震情報のタブ化** — 参考 A 相当 (地震 / リアルタイム / 津波タブ)。
      いまは 1 画面に全部出している。情報が増えて窮屈になったら検討。
- [ ] **観測点の履歴グラフ** — 特定地点の波形風表示。ただし
      「個別観測点の色の変化の検知」は利用条件で名指しされているので、
      **画像からの抽出は不可**。やるなら別のデータ源が要る。
- [ ] **緊急地震速報の履歴** — いまは現況のみ保持していて、過去の EEW は残らない。
- [ ] **通知系設定の URL 固定** — `lat`/`lon`/`tsunami` は URL で決め打ちできるが、
      通知の絞り込み (`eewScope` 等、検討書 §9) は端末の保存値のみ。
      キオスクで決め打ちしたくなったら `UrlKey` に足す。
- [ ] **設定のサーバー側保存** — 現状は端末ごとの localStorage。
      これは §1 の「端末ごとに切り替え」という要件どおりなので、
      むしろ変えないほうがよい。端末が増えて設定が面倒になったときだけ考える。
- [ ] **多重障害時の挙動** — kmoni と P2P が同時に落ちた場合、画面は
      最後のフレームのまま案内だけが出る。「何分前の情報か」を大きく出す
      などの改善余地がある。
- [ ] **ログの外部保存** — いまは Docker の json-file ドライバでローテーション
      (10MB × 3) しているだけ。障害解析を本気でやるなら別途。

## E. 定期的にやること

kmoni は「コンテンツ・配信形態を予告なく変更/削除しうる」と明記している (§2(4))。
表示が崩れたら、まずこの 2 つを流して前提が変わっていないか確かめる。

```bash
./scripts/check-kmoni.sh                                   # 上流の前提確認
python3 scripts/calibrate-kmoni-map.py --overlay /tmp/o.png # 座標系の再較正
```

期待値からずれていたら `docs/kmoni-endpoints.md` を更新すること。

P2P地震情報のレート制限 (2026年6月から IP あたり WebSocket 2 本) も
変更されうる。告知は https://p2pquake.hatenablog.jp/ で流れる。
